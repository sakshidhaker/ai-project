TITLE: PYTHON GENERATED-CODE DEBUGGING AND QUALITY CHECKS

PURPOSE:
Provide the model with a compact checklist for avoiding common mistakes when generating Python code.

SYNTAX CHECK:
Python indentation must be consistent. Function bodies must be indented. Parentheses, brackets, and quotes must match.

IMPORT CHECK:
Every module used by name must be imported. For example, code using random.choice() normally needs import random.

NAME CHECK:
Variables and functions must be defined before they are used.

LOGIC CHECK:
For a game such as Rock Paper Scissors, the result depends on both the user choice and computer choice. A single-choice function cannot decide a winner correctly unless the other choice is supplied.

TYPE CHECK:
input() returns text. Convert numeric input with int() or float() when arithmetic is required.

CASE CHECK:
If a program compares strings such as rock/paper/scissors, use one consistent case or normalize input with lower().

FUNCTION CHECK:
A function should have one clear responsibility and should return a useful value when another part of the program needs the result.

FILE CHECK:
Use with open(..., encoding="utf-8") so files are closed automatically.

ERROR CHECK:
Use try/except for expected input/file errors. Do not hide every error with a bare except.

RUNNABLE PROGRAM CHECK:
When a user asks for a complete script, define the functions and provide a clear starting point such as:

```python
if __name__ == "__main__":
    main()
```

EXAMPLE OF A COMMON BUG:

Bad:
```python
computer_choice = random.choice(["rock", "paper", "scissors"])
```

Better:
```python
import random

computer_choice = random.choice(["rock", "paper", "scissors"])
```

EXAMPLE OF A LOGIC BUG:

Bad idea:
```python
def outcome(choice):
    if choice == "rock":
        return "You win"
```

Why it is wrong:
The winner cannot be known from one choice alone.

Better:
```python
def decide_winner(user_choice, computer_choice):
    if user_choice == computer_choice:
        return "It's a tie!"

    if (
        (user_choice == "rock" and computer_choice == "scissors")
        or (user_choice == "scissors" and computer_choice == "paper")
        or (user_choice == "paper" and computer_choice == "rock")
    ):
        return "You win!"

    return "You lose!"
```

FINAL GENERATION CHECKLIST:
1. Is it actually Python?
2. Are all imports present?
3. Is the indentation valid?
4. Are variables/functions defined before use?
5. Does the logic use all inputs needed to answer the problem?
6. Is the code complete enough to run?
7. Does it actually satisfy the user's request?
