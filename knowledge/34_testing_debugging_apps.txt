TITLE: TESTING AND DEBUGGING APPLICATIONS

PURPOSE:
To teach how to verify code quality using automated tests and how to trace bugs systematically to their root cause.

WHAT IS IT?
Testing is writing code that checks whether your application code behaves correctly under expected and unexpected conditions. Debugging is the disciplined process of finding and removing bugs when tests or users expose a failure.

WHY IS IT USEFUL?
Manual testing by clicking through an app becomes slow, incomplete, and error-prone as features grow. Automated tests run in seconds and give you confidence that adding a new feature did not break existing functionality.

CORE CONCEPTS:

unit tests: Testing a single function or small unit of logic in total isolation.

integration tests: Testing how two or more components work together (for example, testing an API endpoint calling a database).

end-to-end (E2E) tests: Testing the entire application path from user interface down to the database and back.

pytest: The standard, widely adopted testing framework in Python.

assertions: Statements (assert condition) that verify expected outcomes; if false, the test fails.

fixtures concept: Reusable setup and teardown helpers in pytest that prepare test data or mock connections before a test runs.

mocking: Replacing slow or external dependencies (like external LLM API calls or live credit card charges) with simulated responses during tests.

testing success/failure paths: Writing tests for valid inputs (happy path) as well as invalid inputs, missing data, and error conditions (failure paths).

API testing: Sending mock HTTP requests to Flask endpoints using Flask's test client and validating the status code and JSON output.

root-cause debugging: Tracing an error back to where bad state was first introduced, rather than patching over the crash site.

SIMPLE EXPLANATION:
Automated testing is like an automated vehicle inspection line. Instead of taking the car on the highway to see if the brakes work, a machine runs standardized checks on the brake pads, lights, and tire pressure before the car leaves the garage.

def add(a, b):

def divide(a, b):
if b == 0:
raise ValueError("Cannot divide by zero")
return a / b

def test_add_success():
assert add(2, 3) == 5
assert add(-1, 1) == 0

def test_divide_by_zero():
import pytest
with pytest.raises(ValueError):
divide(10, 0)

Testing a Flask API Endpoint with a Test Client:

In test_api.py
import pytest
from app import app

@pytest.fixture
def client():
app.config["TESTING"] = True
with app.test_client() as test_client:
yield test_client

def test_health_route(client):
response = client.get("/health")
assert response.status_code == 200
assert response.get_json() == {"status": "ok"}

def test_chat_missing_message(client):
# Failure path test: verify endpoint returns 400 when message is missing
response = client.post("/api/chat", json={})
assert response.status_code == 400

COMMON MISTAKES:

Only testing the happy path and never testing empty strings, missing fields, or invalid types.

Calling real external paid APIs during automated test runs instead of mocking them.

Writing brittle tests that depend on specific execution order instead of being independent.

Catching exceptions with broad try/except blocks and ignoring the stack trace during debugging.

WHEN TO USE:
Use pytest for every reusable library, API route, validation helper, and data processing pipeline.

WHEN NOT TO USE:
Do not write end-to-end tests for every tiny cosmetic UI tweak. Focus unit and integration tests where business logic, calculations, and security checks happen.
